# naia-memory 기억 정정·삭제 연구 보고서

2026-09-15 · Azure Foundry 크레딧 실행 az1~az6 · 브랜치 `feat/episode-filter-remeasure`(로컬, 공개 전)

## 요약

기억이 틀리게 남는 원인은 검색 순위가 아니라 사실의 생명주기에 있었다. 추출기가 서로 다른 속성에 같은 넓은 분류 id를 붙이면 제품이 옛 사실을 지웠다. 한 발화에서 나온 두 사실이 서로를 덮어쓰기도 했다. 값을 말하지 않은 삭제 요청은 근거 검증에서 막혀 검증기까지 가지 못했다. 이 네 가지를 규칙으로 고치자 합성 42사례의 사실 상태에서 효과가 드러났다. 잘못된 대체는 5건에서 2건으로, 반영된 삭제 요청은 9건 중 3건에서 7건으로 바뀌었고, 잘못 지운 사실은 0건이었다. 모든 수치는 미리 등록한 행 단위 예측과 대조했다.

원문 대화가 지워진 값을 계속 공급하는 문제도 있다. 이를 막는 필터는 대체 정밀도가 낮던 az3에서는 정답 3행을 잃게 했다. 규칙이 들어간 뒤인 az6에서는 비용이 관측되지 않았고, 삭제 누출 1행을 없앴다. 필터의 해로움이 대체 정밀도에 달려 있었다는 해석과 행 단위로 일치하는 결과다.

이 결론에는 범위가 있다. 합성 사례, 휴리스틱 모순 필터 경로, 작성자 1인 판정에서 나온 결과다. 제품 기본 경로(LLM 모순 필터)와 독립 평가는 아직 없다. 게이트는 여전히 통과하지 못했다.

## 실험 흐름

각 실행은 앞 실행이 드러낸 문제 하나를 바꿔 측정했다. 실행마다 사전 등록을 고정한 뒤 돌렸고, 결과는 Fable 검토를 거쳐 이슈 nextain/naia-memory#40에 남겼다.

1. **az1: 첫 실측, 하네스 편차 발견.** 러너가 모든 질의에 시점 조회 인자를 넘겨 최신 질의가 대체된 사실까지 불러왔다. 그래서 naia가 단순 벡터 검색보다 7.7%p 낮게 나왔는데, 이는 설계 차이가 아니었다.
2. **az2: 편차를 고친 재실행.** naia와 단순 벡터 검색의 차이는 사라졌다(+2.6%p, 구간 0~7.7). 남은 실패를 따라가 보니 공통 기전은 원문 에피소드가 사실 생명주기를 거치지 않는다는 점이었다. 삭제 실패는 근거 검증과 구조 필드 부재에서 멈췄다.
3. **az3: 원문 제외 필터, 부정 결과.** 필터를 넣자 현재 정답이 43에서 40(/45)으로 줄었다. 사실이 같은 3행을 열어 보니 모두 잘못 대체된 사실을 원문이 메우던 경우였다. 이 결과로 계획 순서를 바꿔 대체 정밀도를 먼저 다뤘다. 이 실행부터 추출이 비결정적이라는 점(같은 입력에서 약 20/57행이 달라짐)이 드러났고, 이후 실행은 봉인된 추출 응답을 재생해 측정했다.
4. **az5: 대체 규칙 두 가지.** 같은 발화에서 나온 사실끼리는 대체하지 않게 했다. 넓은 범주 id는 속성 라벨까지 같아야 대체하게 했다. 잘못된 대체가 5건에서 2건으로 줄었고, 올바른 대체 6건은 유지되었다.
5. **az4: 삭제 규칙 두 가지.** 속성 이름을 명명한 명시적 삭제 요청은 값이 없어도 근거로 인정하되, 같은 속성의 값이 하나뿐일 때만 허용했다. 구조 없는 사실은 내용이 정확히 같을 때만 삭제 후보로 올렸다. 반영된 삭제가 3건에서 7건으로 늘었고, 잘못 지운 사실은 0건이었다.
6. **az6: 필터 재측정.** 저장소 상태와 삭제 검증까지 재생해 필터만 바꿨다. 제외 방식은 공급 맥락이 예측과 228/228행 일치했다. ko-14 누출이 사라지고 en-04가 정답이 되었으며, 관측된 비용은 없었다. 강등 방식은 공급 집합을 바꾸지 않아 이 스위트로는 판별할 수 없었다.

실행 이름의 번호는 계획한 순서를 따른다. az4는 대체 규칙이 먼저 필요하다는 판단에 따라 az5 뒤에 실행했다.

## 등록된 잔차

아래 문제는 알려진 채로 남아 있다. 결과를 읽을 때 규칙 실패로 오해하지 않도록 사전 등록에 미리 적었다.

- **추출 의미 오류 (ko-09, ja-10).** 추출기가 상황별 선호를 하나의 값으로 내거나, 시도를 선호 변경으로 냈다. 라벨까지 같아서 저장 규칙으로는 막을 수 없다.
- **추출 쪽 삭제 실패 (en-05, en-14).** 추출기가 발화에 없는 값을 인용문으로 적었거나, 속성 이름을 정규화해 인용문과 맞지 않았다. 고치려면 추출 프롬프트를 바꿔 별도 실행으로 측정해야 한다.
- **에피소드 단위 앵커의 한계 (ko-05).** 한 발화가 살아 있는 다른 사실의 앵커이면 지워진 값도 그 발화를 통해 계속 공급된다. 사실 단위로 가리는 방식은 이후 설계 과제다.
- **제품 기본 경로 미측정.** LLM 모순 필터 경로에서는 같은 주어의 사실이 LLM 판단으로 대체될 수 있다. 범주 규칙은 이 경로를 다루지 않는다.
- **비신뢰 출처 충돌 차단의 불일치.** assistant나 tool에서 온 사실의 충돌 판정(`sameSingleIdentity`)은 여전히 id만 본다.
- **형제 값 검사의 회귀 테스트 미작성.** 형제 값이 검색 상위 결과 밖에 있어도 막히는지 consolidation 수준에서 확인하는 테스트가 없다. 지금은 삭제 연산에 항상 프로젝트 전체 사실 집합이 들어가서 문제가 없다.
- **후보 경로 태그.** 한 사실이 여러 경로에서 잡히면 마지막 태그만 남는다. sources 배열로 바꿔야 한다.
- **검증기의 다중 후보 선별 미검증.** 도달한 삭제는 모두 후보가 1개였다.
- **SQLite 경로 미실행.** 규칙은 consolidation에 있어 어댑터와 무관하지만, SqliteAdapter에서 돌려 본 적은 없다.
- **답변과 판정의 노이즈.** temperature 0에서도 맥락이 같은 행의 답변이 약 12/57행 바뀐다. 답변 수준 집계는 방향으로만 읽는다.

## 소유자 결정 항목

- **원문 제외 필터를 제품에 넣는 방식.** 권고는 옵션으로 넣고 휴리스틱 경로에서만 기본으로 켜는 것이다. LLM 모순 필터 경로는 측정한 뒤 정한다.
- **브랜치 묶음을 main에 올릴지.** 대상은 `feat/supersession-precision`, `feat/delete-rule`, `feat/episode-filter-remeasure`다. 저장소가 공개이므로 원시 공급자 응답과 영수증 파일의 포함 여부, 비밀 값 마스킹을 먼저 검토해야 한다. 라이브 naia-agent에는 반영하지 않았다.
- **기본 삭제 검증기.** 기본값이 클라우드 gemini-2.5-flash라서 기본 설정에서는 사실 텍스트가 외부로 나간다. 로컬 추론 원칙과 충돌하므로 로컬 모델 기본값이나 필수 설정으로 바꾸기를 권한다.
