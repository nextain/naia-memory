# Naia Memory 제품 배선 완료 시점 성능 보고서

작성일: 2026-08-24
대상: `naia-memory` ↔ `naia-agent` ↔ `naia-shell`

## 결론

배선은 완료됐고 제품에서 사용할 수 있는 단계다. 다만 현재 제품에 연결된 것은
`naia-memory`의 완성된 기본 경로인 `LocalAdapter`다. 지금 연구 브랜치에서
진행 중인 MIRACL 다국어 검증, 경쟁 엔진 비교, 대규모 검색 경로 개선이 제품에
실시간으로 자동 반영되는 구조는 아니다. 연구 결과를 검증하고 릴리스 가능한
변경만 `naia-memory`에 병합한 뒤, `naia-agent` 의존성 및 통합 테스트를 거쳐
`naia-shell`에 순차 반영한다.

따라서 현 상태를 한 문장으로 표현하면 다음과 같다.

> 실제 제품 배선은 완료됐고 한국어 기본 검색 능력은 강하지만, 경쟁 메모리
> 엔진보다 기억 업데이트를 더 잘한다는 제품 차원의 주장은 아직 검증 중이다.

## 배선 완료 범위

| 계층 | 완료 내용 | 확인 기준 |
| --- | --- | --- |
| `naia-memory` | 저장·회상·압축·인지 기능을 `MemoryProvider` 계약 뒤에서 제공 | 기본 구현은 `LocalAdapter` |
| `naia-agent` | 메모리 제공자를 대화 런타임에 연결하고 메모리·지식 저장 위치를 ADK의 `naia-settings` 아래로 고정 | 원격 `main` `bd70c44c39d32f693eab99994374194c21e37f7f` |
| `naia-shell` | Agent가 관리하는 메모리·지식 경로를 읽고 설정 UI/호스트 경계를 유지 | 원격 `main` `7aa90a8e62782139a43683d97f38865086d8acf4` |

검증 시점에 Agent 테스트와 빌드가 통과했고, Shell은 프런트엔드 52개와 Rust
231개 테스트 및 Shell-Agent 프로토콜 연결 검증을 통과했다. 이것은 “배선이
동작한다”는 증거이며, 장기 대화에서의 기억 품질 우위를 직접 증명하는 수치는
아니다.

## 배선 완료 시점에 기대할 수 있는 성능

### 1. 검색 품질

현재 가장 강한 독립 지표는 MIRACL 한국어 전체 코퍼스 검색이다. 1,486,752개
문서와 213개 질의에서 Naia 기본 검색 경로는 다음 결과를 냈고, NIST
`trec_eval`로 지표를 재현했다.

| 지표 | Naia | 동 프로토콜 역사적 MIRACL BM25+mDPR | 차이 |
| --- | ---: | ---: | ---: |
| nDCG@10 | 0.6526 | 0.6090 | +0.0436 |
| Recall@100 | 0.9233 | 0.9000 | +0.0233 |
| Success@1 | 0.5962 | 비교값 없음 | - |
| Success@10 | 0.9202 | 비교값 없음 | - |
| MRR | 0.7228 | 비교값 없음 | - |

이 결과는 한국어에서 관련 정보를 찾는 기본 검색기가 약하지 않다는 강한
증거다. 그러나 사용한 임베딩 모델이 MIRACL 학습 분할을 사용했다고 공개하고
있으므로, 제로샷 일반화나 Naia 고유 알고리즘의 우위로 해석하면 안 된다.

### 2. 지연과 규모

SQLite 고성능 경로의 100,000개 사실 CPU 벤치에서는 surface p50 4.00ms,
p95 5.34ms, deep p50 40.68ms, p95 43.78ms가 측정됐다. 주입 처리량은 초당
1,631개 사실, RSS는 약 288MB, DB는 약 196MB였다. MIRACL 한국어 148만 문서
exact 검색은 평균 질의 지연 202.10ms, 최대 1,040.76ms였다.

단, 이 수치는 제품 기본 경로인 `LocalAdapter`의 end-to-end 대화 지연과
동일하지 않다. `SqliteAdapter`는 대규모 검색 경로이며 감정 게이팅, 시점
앵커링, 지식 그래프 연관, 통찰 추출이 아직 LocalAdapter와 완전 동등하지 않다.

### 3. 실시간 컨텍스트 압축

rolling-summary 팽창 결함을 수정해 벤치 압축률이 161.8% 팽창에서 29.7%로
개선됐다. 결정론적 폴백의 사실 보존율은 약 30~50% 범위가 한계였고, 벤치용
LLM 요약기 경로는 16.5% 크기로 압축하면서 앵커 사실 90%를 보존했다.

따라서 제품에서 고충실 압축을 원하면 Agent가 LLM summarizer를 명시적으로
주입해야 한다. 결정론적 경로는 빠르고 비용 없는 안전 폴백이지, 고충실 요약의
대체재는 아니다.

## 지금 개선 중인 내용은 실시간 반영되는가

아니다. 의도적으로 순차 반영한다.

1. `naia-memory` 연구 브랜치에서 가설을 구현하고 벤치한다.
2. 과적합·데이터 누출·비교 프로토콜 불공정을 적대 검토한다.
3. 재현 가능한 품질 향상이 확인된 코드만 병합 후보로 만든다.
4. `naia-agent`가 새 패키지/계약을 받아 저장·회상·컨텍스트 주입을 통합 검증한다.
5. `naia-shell`에서 사용자 설정, 경로, 재시작·복구, 실제 대화 흐름을 검증한 뒤
   배포한다.

현재 MIRACL 영어 primary 실행 준비와 다국어 전이 검증, Graphiti·Hindsight·
Mem0·Letta 비교 하네스는 연구 단계다. 이 작업은 벤치 증거와 안전한 제품 변경을
가려내기 위한 것이며, 실행 중인 제품 바이너리를 즉시 바꾸지 않는다.

## 현재 제품 가치와 한계

현재 공개해도 방어 가능한 가치는 다음 세 가지다.

- 로컬 우선 저장이며 메모리와 지식의 소유 경계가 `naia-settings`로 명확하다.
- 한국어 148만 문서 전체 코퍼스에서 강한 기본 검색 성능을 재현했다.
- 단순 벡터 저장소가 아니라 갱신·모순·시간·감쇠·지식 그래프를 다루는 인지
  메모리 구조를 제품 런타임 계약 뒤에 연결했다.

아직 공개하면 안 되는 주장은 다음과 같다.

- 글로벌 메모리 엔진 전체 대비 SOTA
- Mem0, Hindsight, Graphiti, Letta보다 기억 업데이트를 더 잘한다는 확정 주장
- 영어·일본어·아랍어까지 한국어와 같은 수준이라는 다국어 주장
- SQLite 대규모 경로가 LocalAdapter의 모든 인지 기능을 대체한다는 주장

## 제품 반영 전 남은 게이트

1. 영어 primary MIRACL 전체 코퍼스 실행을 완료하고 한국어 결과의 전이 여부를
   확인한다.
2. 일본어 또는 아랍어를 포함해 언어별 실패 패턴을 분리한다.
3. 동일 입력·동일 채점 규칙으로 Mem0, Hindsight, Graphiti, Letta와 충분한
   표본의 lifecycle/update 벤치를 수행한다.
4. Naia의 핵심 차별점인 supersession, contradiction, temporal update를 제품
   Agent 루프에서 UC/FE/E2E로 검증한다.
5. 유의미한 개선만 `naia-memory` main → `naia-agent` → `naia-shell` 순서로
   올리고 회귀 테스트 후 배포한다.

## 최종 판정

배선 품질은 배포 후보 수준이다. 검색 성능은 한국어 기준으로 충분히 경쟁력
있으며, “최소한 이 정도는 된다”는 근거도 있다. 하지만 Naia만의 차별점인
기억 업데이트 품질은 아직 공개 경쟁력 보고서의 최종 증거가 부족하다. 지금
개선 루프의 목적은 검색 모델의 성능을 제품 성능으로 오인하지 않고, 실제
장기 대화에서 오래된 사실을 버리고 최신 사실을 정확히 유지하는 능력을 동일
조건 경쟁 엔진 대비 증명하는 것이다.
