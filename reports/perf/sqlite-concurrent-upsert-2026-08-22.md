# SQLite 동시 upsert 성능 개선 — 2026-08-22

## 결론

`SqliteAdapter.semantic.upsert()`의 같은 이벤트 루프 틱 동시 요청을 최대 1,000건씩
하나의 워커 트랜잭션으로 묶었다. 개별 Promise는 해당 트랜잭션 커밋 뒤에만 완료되고,
한 항목이 실패하면 같은 배치의 모든 Promise가 거부되며 전체 배치가 롤백된다.

같은 머신의 10,001건 즉시 전후 비교에서 처리량은 6,563 facts/s에서
13,746–14,051 facts/s로 2.10–2.14배 개선됐다. 후자는 5회 반복 범위다.

## 10만 건 현재값

환경은 Linux 7.0.9, Node v26.3.0, Intel i9-13900K, 384차원 결정론적 임베더다.
10만 facts, hot 1만, 쿼리 300표본 결과:

| 측정값 | 결과 |
|---|---:|
| 주입 처리량 | 16,798 facts/s |
| surface p50 / p95 | 14.04 / 15.89 ms |
| deep p50 / p95 | 39.14 / 49.95 ms |
| RSS / DB 파일 | 382.9 / 220.8 MB |

원시 영수증은 `latency-accuracy-count100000.json`에 있다. 과거 보고서의
1,631 facts/s 대비 10.3배 차이는 코드 외 변화가 섞였으므로 이 패치의 인과 효과로
사용하지 않는다.

## 주장 한계

이 개선은 대규모 저장 처리량과 검색 지연 축의 증거다. 다국어 기억 업데이트 품질,
경쟁 엔진 대비 정확도, 독립 보유셋 성능을 증명하지 않는다. 공개 경쟁력 판정은 #39의
독립 코퍼스·독립 운영자·동일 입력 경쟁 엔진 영수증 게이트가 여전히 필요하다.
