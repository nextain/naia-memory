# 삭제 값 가림 탐색 확인 (증거 아님)

제품은 879a1cf다. 분리 필터(82e7d5d) 위에 두 가지를 더했다. 첫째, 정리 결과에 삭제마다 멈춘 자리를 남긴다(d524673, 관측 전용). 둘째, 최신 회상에서 삭제된 사실의 원문이 살아 있는 다른 사실의 근거이기도 하면, 지운 값만 `[deleted]`로 가린다. 규칙 전 실행의 봉인 추출을 재생했고 삭제 검증과 LLM 필터는 실제로 호출했다. 이 실행에서는 답변 판정을 하지 않았다.

## 확인셋 120건

- 사실 상태와 검색 맥락이 분리 필터 실행과 648행 모두 같다. 가림은 한 번도 일어나지 않았다.
- 맥락 수준 삭제 누출(취소 사례 제외, forget·delete_one 24건 중): naia 6건, LLM 필터 경로 6건으로 분리 필터와 같다.
- 남은 6건은 모두 삭제가 적용되지 않은 사례라서, 가림으로는 닿지 않는다.
  - ko-043, ko-046: 추출 단계 근거 검사에서 거부됐다(target-lacks-value-and-identity). 추출기가 붙인 속성 id가 어휘에 없어 지워졌고, 사용자가 부른 이름("이메일 비밀번호", "그 클라우드 접속 암호")이 속성 이름("테스트용 가상 이메일 비밀번호", "가상 클라우드 접속 암호")을 포함하지 않는다.
  - ko-111: 근거 인용 앞에 추출기 프롬프트의 `[Date: 2026-07-03]` 표지가 붙어 전체 발화와 달랐다(evidence-not-whole-episode).
  - ko-045, ko-113: 원래 값이 구조 없는 사실로 저장돼, 내용이 같아야 하는 후보 조건에 걸리지 않았다(no-candidate).
  - ko-119: 원래 발화에서 사실이 추출되지 않았고, 값("수지야")은 발화에만 있다(no-candidate).
- 예약 취소 12건 중 삭제가 적용된 경우는 1건이다. 6건은 다른 값을 지우지 않는 규칙(value-mismatch)에 막혔고, 5건은 삭제 요청이 추출되지 않았다.

## 첫 번째 셋 84건

- 가림은 ko-32(캠핑장 A·B구역 중 A 취소)에서 한 번 일어났다. 원래 발화 "주말 캠핑장 A구역과 B구역 두 군데 신청했어."는 B구역 사실의 근거라서 남고, 취소된 A구역만 가려졌다. 의도한 동작이다.
- 맥락 수준 누출은 12건 중 1건(ko-84)으로, 원문 제외 필터 실행과 같다. ko-84는 속성 이름 "테스트 계정 비밀번호(서리 프로젝트)"와 사용자가 부른 이름 "서리 프로젝트의 테스트 계정 비밀번호"의 어순이 달라 추출 단계에서 거부됐다.
- 예약 취소 ko-31, ko-34의 삭제 요청도 `[Date: ...]` 표지 때문에 추출 단계에서 거부됐다.

## 해석

가림은 올바르게 동작하지만, 이 두 셋에서 남은 누출은 가림이 닿지 않는 곳에 있다. 삭제가 애초에 적용되지 않았기 때문이다. 다음 단계는 적용 경로를 넓히는 것이다. 추출기가 만든 날짜 표지를 근거 인용에서 벗기고(3건), 사용자가 부른 이름과 속성 이름을 낱말 단위로 대조하고(2건), 구조 없는 사실은 이름과 값이 둘 다 들어 있으면 후보로 삼는다(2건). ko-046("그 ...")과 ko-119(사실 없음)는 이 변경으로도 남는다.
