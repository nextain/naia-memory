# 한국어 증명 결과: 사실 상태와 답변이 같은 방향으로 움직였지만 사전 등록 기준은 통과하지 못했다

한국어 독립 보유셋 84건에서, 2026-09-15 규칙을 넣기 전 제품(70dc147)과 넣은 뒤 제품(a0dd0b5)을 같은 추출로 비교했다. 규칙 후 실행은 규칙 전 실행의 봉인 응답 84건을 재생했다. 사실 상태 비교는 점수를 열기 전에 커밋했다(22cd126). 유효 조건은 모두 통과했다. 규칙 전 실행은 실제 추출 84건, 규칙 후 실행은 재생 84건이었고, LLM 필터는 14회와 15회 호출에 휴리스틱 대체 0건이었다.

## 1차 지표: 사실 상태

사실 상태 오류(잘못된 대체, 삭제 미반영, 잘못된 archive)가 있는 사례는 휴리스틱 경로에서 20건에서 9건으로, LLM 필터 경로에서 19건에서 9건으로 줄었다. 늘어난 곳과 줄어든 곳은 다음과 같다.

- **날짜 사례 (new/deadline):** 휴리스틱 경로의 잘못된 대체가 4건에서 0건으로 줄었다. "마감일"과 "만나기로 한 날짜"가 같은 분류 id로 묶여 마감일이 지워지던 문제로, 범주 정체성 규칙이 막았다.
- **비밀값 삭제 (delete/forget):** 삭제 반영이 6건 중 2건에서 6건으로 늘었다. 값을 다시 말하지 말라는 요청이 이제 반영된다.
- **프로젝트 한쪽 삭제 (project_isolation/delete_one):** 삭제 반영이 6건 중 1건에서 4건으로 늘었고, 남겨야 할 다른 프로젝트 값을 지운 경우는 없었다.
- **동시 선호 (preferences/coexist):** 오류가 3건에서 2건으로 줄었다.
- **예약 한쪽 취소 (delete/cancel_one):** 오류가 늘었다. 휴리스틱 경로 4건에서 5건, LLM 경로 3건에서 5건이다.

사전 등록 기준으로는 통과하지 못했다. 14구성군 클러스터 부트스트랩 구간은 휴리스틱 경로 [−24, 0], LLM 경로 [−23, +2]로 모두 0을 포함한다. 등록한 문구 규칙에 따라 "차이 없음"으로 적는다. 하드 조건인 "규칙 후 잘못된 archive 0"도 깨졌다. 두 경로 모두 ko-36에서 남겨야 할 치과 예약이 archive되었다.

## ko-36: 잘못 지워진 예약

사용자는 "치과와 피부과 예약을 둘 다 잡아 줘" 뒤에 "피부과는 취소하고 치과만 유지해 줘"라고 했다. 추출기는 첫 발화에서 치과 예약만 사실로 저장했다. 피부과 취소 요청이 들어오자, 기존 후보 선정 규칙이 같은 분류(plan:activity)의 값이 하나뿐이라는 이유로 값이 다른 치과 예약을 후보로 올렸다. 이 규칙은 2026-09-15 이전부터 있었다. 규칙 전 실행에서는 검증기가 이 후보를 거부했고, 규칙 후 실행에서는 승인했다. 두 실행의 차이는 규칙 후 제품이 검증기에 후보의 속성 이름("의료 예약")을 함께 넘긴다는 점이다.

az4 사전 검사에서 세 번째 삭제 규칙으로 "삭제 후보는 사용자가 지목한 값과 같은 사실로 한정"을 계획했으나 구현하지 않았다. 이번 실패는 그 빈틈에서 나왔다.

## 판정 방식의 한계와 수정 항목

첫째, ko-34의 LLM 경로에서는 규칙 전 "삭제 반영"이 규칙 후 "삭제 미반영"으로 바뀌어 퇴보처럼 보인다. 그러나 규칙 전의 반영은 LLM 필터가 오전 10시 미팅을 오후 2시 미팅으로 잘못 대체한 결과였다. 이번 규칙 후에는 같은 발화 규칙이 이 대체를 막았다. 삭제 요청 자체는 두 실행 모두 추출기가 증거 인용문에 날짜 태그를 붙여 근거 검증에서 거부되었다. 사실 상태 스크립트가 상태를 보지 않고 은퇴 여부만 봐서 이 경우를 반영으로 셌다. 이는 한계가 아니라 고칠 항목이다. 다음 판부터 archived만 삭제 반영으로 세고, superseded는 잘못된 대체로 분류한다.

둘째, 판정 불가(unmatched)가 84사례 중 14건으로, 개발 사례의 한국어 1건보다 훨씬 많다. 이번 보유셋의 값이 "지하철을 타는 게 편해" 같은 구절이라 저장된 표기와 어긋났다. 그만큼 판정된 사례가 줄었다.

셋째, 교차 비교 스크립트는 사전 등록의 primary_metric.analysis_script에 sha와 함께 등록되어 있고, 분석은 등록 문구(14구성군, seed 20260915, 10,000회)대로 했다. 클러스터 부트스트랩이 효과가 몰린 경우 보수적이라는 점은 결과를 해석하는 근거가 아니라 다음 사전 등록의 설계 근거로 옮긴다.

## 2차 지표: 답변 (잠정)

사람 검수(1단계)가 아직 끝나지 않아 판정 모델 결과는 잠정이다.

- **삭제 누출:** 30건 중 11건에서 1건으로 줄었다(두 경로 모두).
- **옛 값 노출:** 휴리스틱 경로 4건에서 2건, LLM 경로 3건에서 1건으로 줄었다.
- **치명적 역전:** 휴리스틱 경로 9건에서 2건, LLM 경로 10건에서 1건으로 줄었다.
- **현재 정답:** 휴리스틱 경로 81/90에서 83/90으로 늘었고, LLM 경로 83/90에서 80/90으로 줄었다. LLM 경로의 규칙 후 실행에는 판정 불가 2건이 있다.
- **전체 정답:** 휴리스틱 경로 91/114에서 98/114, LLM 경로 91/114에서 96/114로 늘었다.

같은 방식의 클러스터 구간은 모두 0을 포함한다. 예를 들어 휴리스틱 경로 삭제 누출 차이는 −10, 구간 [−25, 0]이다. 노이즈 기준인 simple-vector 팔은 두 실행에서 공급 맥락이 같은데도 현재 정답이 80에서 77로 바뀌었고, 규칙 후 실행에서 판정 불가가 8건 있었다. 게이트는 두 실행 모두 FAIL이다. 규칙 후 실행에 남은 실패는 삭제 누출 1, false_overwrite 5, 역전 2(LLM 경로 1)다.

## 해석

규칙 묶음은 한국어 새 사례에서 사실 상태와 답변 양쪽 모두 예측한 방향으로 움직였다. 변화가 가장 큰 곳은 삭제 요청의 반영과 삭제 누출이다. 그러나 사전 등록한 통계 기준은 효과의 집중 때문에 넘지 못했고, 잘못 지운 사실 0건이라는 하드 조건은 기존 후보 규칙의 빈틈 때문에 깨졌다. 이 결과만으로 "한국어에서 개선이 증명되었다"고 쓸 수는 없다. "예측 방향의 변화가 관측되었으나 등록 기준을 통과하지 못했고, 해결할 결함 하나가 드러났다"까지가 정직한 표현이다.
