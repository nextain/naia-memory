# R3 탐색 확인 (증거 아님)

1차 한국어 보유셋은 ko-36 결함을 찾는 데 쓰였으므로 개발에 노출된 자료다. 이 실행은 R3(366141b: 값을 지목한 삭제는 다른 값을 가진 사실을 후보로 올리지 않음)가 의도대로 동작하는지 보는 탐색 확인이며, 사전 등록이 없다. 규칙 전 실행(70dc147)의 봉인 추출 84건을 재생했고, 삭제 검증과 LLM 필터는 실제로 호출했다.

## 결과

- **ko-36:** 두 경로 모두에서 잘못된 archive(치과 예약)가 사라졌다.
- **휴리스틱 경로:** 삭제 반영은 11건으로 a0dd0b5와 같았고, 그 밖의 사실 상태도 달라지지 않았다.
- **LLM 필터 경로:** ko-33이 "삭제 반영"에서 "삭제 미반영"으로 바뀌었다. 그러나 a0dd0b5에서 archive된 사실은 "요가 클래스 등록은 취소하고 필라테스 클래스만 남김"이었고, 이 사실의 구조화 값은 필라테스 클래스다. 남겨야 할 값을 가진 사실이 지워진 것을 스크립트가 문장 속 "요가" 글자 때문에 반영으로 센 오분류다. R3는 이 잘못된 삭제를 막았다.

## 수정 항목

사실 문장에 두 값이 함께 들어 있으면 글자 매칭이 틀린다. 확인 실행 전에 두 가지를 바꾼다. 러너는 사실의 구조화 값을 trace lineage에 기록한다(관측 전용, 판정 입력 아님). factstate는 구조화 값이 있으면 그 값으로 먼저 대조하고, 없을 때만 문장 대조로 넘어간다. 또한 archived만 삭제 반영으로 세고, superseded는 잘못된 대체로 분류한다(1차 결과 노트의 수정 항목).
