# 한국어 독립 보유셋 작성 지침

이 문서는 작성 에이전트에게만 주는 지침이다. 작성자는 naia-memory의 코드, 기존 평가 사례, 실행 결과를 보지 않는다. 작성물은 rows.json 하나이며, 입력·정답 파일은 별도 스크립트가 기계적으로 만든다.

## 목적

AI 비서가 사용자와 나눈 대화를 기억하고, 나중 질문에 지금 사실대로 답하는지 평가한다. 사례마다 사용자의 발화 2~3개와 질문 1~2개, 정답 명제, 그리고 답에 나오면 안 되는 옛 명제를 적는다.

## 형식

rows.json은 객체 배열이다. 각 객체:

- `category`: new, update, delete, contradiction, preferences, history, project_isolation 중 하나
- `variant`: 아래 표의 변형 이름
- `turns`: 사용자 발화 문자열 배열 (2개, delete_one만 3개). 모두 사용자가 비서에게 하는 반말 또는 해요체 한국어. 각 발화는 한두 문장.
- `question`: 첫 질문
- `expected`: 첫 질문의 정답 명제 (평서문 한 문장)
- `obsolete`: 답에 나오면 안 되는 옛 값이나 잘못된 결론의 명제. 없으면 빈 문자열.
- `second`: 두 번째 질문이 있는 변형만 `[질문, 정답 명제]`, 아니면 null
- `forbidden_value`: forget 변형만, 지워야 할 값 문자열. 아니면 null

## 변형 (범주마다 2개, 각 6건, 총 84건)

| category | variant | 구조 |
|---|---|---|
| new | stable | 1턴: 기억해 달라는 사실. 2턴: 같은 주제의 다른 사실이지만 1턴을 바꾸지 않음(방해). 질문은 1턴 사실. obsolete 없음. |
| new | deadline | 1턴: 어떤 일의 날짜나 시각. 2턴: 관련은 있지만 다른 일의 다른 날짜, "~와는 다른 날짜야"처럼 구분을 명시. 질문은 1턴의 날짜. obsolete 없음. |
| update | correction | 1턴: 수량·이름·값. 2턴: "잘못 말했어, ~가 맞아"로 정정. 질문은 현재 값. obsolete는 1턴 값. |
| update | chain | 1턴: 값 A. 2턴: B로 변경. 3턴: 최종 C, "앞서 말한 A와 B는 취소". turns는 3개다. 질문은 최종 값. obsolete는 "A 또는 B". |
| delete | forget | 1턴: 가상의 비밀 값(암호·합언어 등)을 기억해 달라 하며 "테스트용 가상"임을 밝힘. 2턴: "기억에서 지워 줘. 값을 다시 말하지 마". 질문: "내 ~를 기억해?". expected는 "~는 삭제되어 알 수 없다". obsolete는 값을 담은 명제. forbidden_value에 그 값. |
| delete | cancel_one | 1턴: 두 가지를 신청·예약·등록. 2턴: 하나를 취소하고 다른 하나는 유지한다고 명시. 질문: 아직 남아 있는 것. expected는 남은 것만. obsolete는 취소된 것이 유지된다는 명제. second: ["취소된 것이 아직 유효해?", "아니요. ~는 취소되었다."] |
| contradiction | quotation | 1턴: 사용자의 선호나 사실. 2턴: 다른 사람의 말을 인용하며 반대 내용을 전하되 "내 ~는 바뀐 게 아니야"로 명시. 질문은 사용자의 선호. obsolete는 인용된 반대 내용. |
| contradiction | hypothetical | 1턴: 현재 상태. 2턴: "만약 ~라면 ~할 수도 있겠지. 아직 안 했어"라는 가정. 질문은 지금 상태. obsolete는 가정된 상태. |
| preferences | coexist | 1턴: 상황 A에서의 선호. 2턴: 상황 B에서의 다른 선호, "A와는 별개야". 질문: 두 상황의 선호를 각각. expected는 둘 다. obsolete 없음. |
| preferences | unchanged | 1턴: 선호. 2턴: 관련 물건을 새로 샀거나 상황이 생겼지만 "선호는 그대로야". 질문은 선호. obsolete는 새 물건·상황을 선호한다는 명제. |
| history | former | 1턴: 담당자·값. 2턴: "이제 ~로 바뀌었어". 질문: 현재 값. obsolete는 1턴 값이 현재라는 명제. second: ["이전 ~는?", "이전 ~는 (1턴 값)이었다."] |
| history | at_time | 1턴: 값. 2턴: "오늘부터 ~로 바꿨어". 질문: "변경 전 시점의 ~는?". expected는 1턴 값이 변경 전 값이라는 명제. obsolete 없음. second: ["현재 ~는?", "현재 ~는 (2턴 값)이다."] |
| project_isolation | different | 1턴: 프로젝트 X의 값. 2턴: 프로젝트 Y의 같은 속성 다른 값. 질문: X의 값. expected는 X 값. obsolete는 X가 Y의 값이라는 명제. second: ["Y의 ~는?", "Y의 ~는 (Y 값)이다."] |
| project_isolation | delete_one | 1턴: 프로젝트 X의 값. 2턴: 프로젝트 Y의 값. 3턴: "X의 ~ 기억만 삭제해 줘. Y는 그대로 둬". 질문: "X의 ~를 기억해?". expected는 "X의 ~는 삭제되어 알 수 없다". obsolete는 X 값 명제. second: ["Y의 ~는?", "Y의 ~는 (Y 값)이다."] |

## 제약

- 84건 모두 소재가 다르다. 같은 명사(예: 담당자, 마감, 수업)를 여러 건에 반복하지 않는다. 일상·취미·업무·가족·동네 등 폭넓게.
- 다음 소재는 쓰지 않는다: 보리차, 커피 원두, 등대, 교정본, 엽서, 답례품, 녹음 시작, 창고 암호, 도예 수업, 사진 수업, 안내문 이메일/문자, 작업 책상, 재즈, 전자음악, 종이 출력본, 태블릿, 아카이브 담당자, 전시 입장료, 검수 담당자, 배포 채널, 해오름, 별무리, 솔, 숲.
- 실제 인물·기업·주소·실제 비밀번호를 쓰지 않는다. 사람 이름은 흔한 가상 이름.
- 값은 서로 헷갈리기 쉬운 것으로 고른다(비슷한 숫자, 같은 부류의 물건). 정답이 발화에 명시적으로 있어야 하고, 추론이 필요한 사례는 만들지 않는다.
- 문장은 자연스러운 한국어 구어체. 번역투를 피한다.
- 프로젝트 이름은 두 글자 한글 고유명(예: 바람, 노을)으로 짓되 위 금지 목록을 피한다.

출력: rows.json (UTF-8, ensure_ascii=False). 다른 파일은 만들지 않는다.
