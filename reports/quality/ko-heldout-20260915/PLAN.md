# 한국어 기억 정정·삭제 증명 계획

2026-09-15 · 소유자 지시: "우선 한국어에 집중해서 증명" · 담당: Claude(실행), Fable(설계·결과 검토), 루크(사람 검수·결정)

## 목표

한국어 대화에서 naia-memory의 정정·삭제 규칙(2026-09-15의 네 가지 수정)이 개발에 노출되지 않은 새 사례에서도 사실 상태와 답변을 개선한다는 것을, 사전 등록한 기준으로 보인다.

## 성공 기준 (사전 등록, 결과 전에 고정)

주장은 두 층으로 나눈다.

1. **사실 상태 (1차):** 보유셋 84건에서 규칙 적용 후 제품이 규칙 적용 전보다 잘못된 대체와 삭제 미반영이 적고, 잘못 지운 사실은 0건이다. 기계적으로 세며 판정 모델이 필요 없다.
2. **답변 (2차):** 현재 정답률이 규칙 적용 전보다 낮지 않고, 삭제 누출과 stale 노출이 줄어든다. 14구성군 클러스터 부트스트랩(구성군당 6건)의 95% 구간이 예측 방향으로 0을 포함하지 않으면 "개선 관측"으로, 포함하면 "차이 없음(근거 없음)"으로 적는다. 1차 지표에도 같은 구간을 쓴다. 판정 모델의 판정은 1단계의 사람 일치율이 90% 이상일 때만 쓴다. 미만이면 사람 판정으로 대체한다.

원 설계의 게이트(현재 정답 85%, 누출 0)는 그대로 보고하되 이 계획의 통과 조건은 아니다. 규칙의 효과를 보이는 것이 목표이지 게이트 통과가 목표가 아니다.

## 범위와 고정 조건

- 언어: 한국어만. 영어·일본어는 이번 범위 밖.
- 사례: 개발 사례와 같은 14개 구성(범주 7 × 변형 2) × 6건 = 84건. 개발 사례를 본 적 없는 별도 모델이 AUTHOR-BRIEF.md만 보고 작성한다. 작성 모델은 Azure의 deepseek-v4-flash이며 저장소에 접근하지 않는다.
- 모델: 추출·답변 gpt-5-4-nano, 삭제 검증·판정 deepseek-v4-flash, 임베딩 CPU multilingual-e5-base. 지금까지의 az 실행과 같다.
- 비교 팔: 규칙 적용 전(70dc147)과 규칙 적용 후(a0dd0b5, 원문 제외 필터 포함)를 각각 휴리스틱 모순 필터와 LLM 모순 필터 두 경로로 돌린다(2×2). 단순 벡터 검색과 기억 없음은 두 실행 모두에 넣어 노이즈 기준으로 쓴다. LLM 모순 필터는 판정 모델과 겹치지 않게 gpt-5-4-nano를 쓴다.
- 로컬 모델 경로: 이번 범위 밖. GPU 사용은 별도 승인.

## 단계와 점검 지점

각 단계 끝에 점검 지점이 있다. 점검을 통과하지 못하면 다음 단계로 가지 않고 원인을 기록한다.

**1단계: 판정 모델 검증.** 루크의 한국어 38문항 검수 결과를 블라인드 대응표로 판정 모델과 대조한다. 점검: 정답 여부 일치율과 삭제·stale 표시의 일치율을 표로 남긴다. 90% 미만이면 2차 기준을 사람 판정으로 바꾼다. (루크 검수 완료 대기)

**2단계: 보유셋 작성과 봉인.** 작성 모델이 rows.json을 쓴다. 기계 검사(건수, 구조, 금지 소재, 중복)를 통과한 뒤 materialize.py로 입력·정답 파일을 만들고 sha256 매니페스트로 봉인한다. 점검: 검사 전부 통과, Fable이 모호한 정답이나 유출(질문에 답이 들어 있음)을 찾지 못함, 루크가 자연스러움을 훑어봄(선택). 봉인 뒤에는 결과를 보고 사례를 고치지 않는다.

**3단계: 사전 등록 고정.** 위 성공 기준, 팔, 모델, 예측을 preregistration.json에 적고 Fable의 "고정·실행 가능" 판정을 받는다. 점검: 러너 sha256과 제품 커밋 기록.

**4단계: 실행.** 규칙 적용 전 실행이 새로 추출하고 응답을 봉인한다. 규칙 적용 후 실행은 그 봉인 응답을 재생해 두 제품이 같은 추출을 보게 한다(추출 프롬프트가 같으므로 가능하며, 재생이 빗나가면 러너가 중단한다). 점검: 재생·봉인 무결성, 추출 실패 게이트, LLM 필터 호출과 휴리스틱 대체 0건, 삭제 검증 호출 수 기록.

**5단계: 판정과 결과.** 사실 상태 판정을 score 전에 커밋한다. 짝 비교와 부트스트랩 구간을 낸다. 점검: 사전 등록 예측과 행 단위 대조, Fable 결과 검토.

**6단계: 보고.** 이슈 #40 기록, 한국어 증명 보고서 갱신, 루크 DM 한 통(결과와 결정 항목).

## 소유자 검수에서 나온 한계와 다음 과제 (2026-09-15)

- **명시적 변경 단서:** 보유셋 발화에 "앞서 말한 A와 B는 취소야", "~는 바뀐 게 아니야", "값을 다시 말하지 마" 같은 주의 문구가 들어 있다. 실제 대화는 이렇게 말하지 않는다. 추출기가 명시적 단서를 받으므로 결과가 실제보다 좋게 나왔을 수 있다. 한국어 증명 결론에는 "변경 의도를 명시적으로 말하는 대화에서"라는 조건을 붙인다. 다음 과제는 주의 문구 없이 자연스럽게 말하는 사례셋, 또는 실제 대화 기록 기반 사례다.
- **떠올린 기억에 남는 삭제 값:** 삭제 요청으로 사실은 archive되었지만, 원천 발화가 같은 발화의 다른 활성 사실의 앵커여서 최신 회상에 계속 공급된다(ko-05). 답변 모델이 스스로 말하지 않았을 뿐, 사용자 관점에서 삭제가 아니다. 의도한 동작이 아니다. 다음 과제는 두 가지다. 첫째, 삭제된 사실의 원천 발화는 다른 사실이 살아 있어도 최신 회상에서 빼거나 해당 값을 가린다(원본은 보관, history 모드 유지). 둘째, 삭제 누출을 답변뿐 아니라 공급 맥락 수준에서도 센다.
