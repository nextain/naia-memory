# 사실 상태 기계 판정의 교정

`factstate.py`는 판정 모델 없이 사례마다 사실 상태를 분류한다. 보유셋에 쓰기 전에, 사람이 이미 판정해 둔 개발 실행 세 개(az3, az5b, az4)에 돌려 사람 판정과 비교했다. 개발에 노출된 자료이므로 결과는 증거가 아니라 스크립트 교정용이다. 개발 사례의 값 필드는 보유셋과 같은 방식으로 작성 모델이 붙였다(`dev-values.json`).

## 사람 판정과의 비교

사람 판정은 az5 조사(`supersession-precision-20260915/listing.txt`)와 az4 판정(`candidate-az4-20260915/fact-state-judgement.md`)을 기준으로 했다.

- **az3 잘못된 대체:** 사람 판정은 5건(ko-01, ko-02, ko-09, ja-09, ja-10)이고, 스크립트는 4건(ko-01, ko-09, ja-09, ja-10)을 찾았다. ko-02는 날짜가 "2026-07-18"로 저장되어 처음에는 판정하지 못했다. 날짜와 금액 표기 변환을 넣은 뒤로는 판정된다.
- **az3 잘못된 archive:** ja-06 요리 교실은 일본어 값이 영어 문장("cooking class on Thursday")으로 저장되어 판정하지 못했다. 언어가 바뀐 저장은 이 스크립트의 한계다. 한국어 보유셋에서는 추출이 한국어로 저장하므로 영향이 작을 것으로 본다.
- **az5b와 az4 잘못된 대체:** 사람 판정과 같은 ko-09, ja-10 두 건이었다.
- **az4 삭제 미반영:** 사람 판정과 같은 en-05, en-14 두 건이었다. az5b에서는 여섯 건(ko/en/ja-05, ko/en/ja-14)으로, az4 이전 상태와 맞는다.

판정된 사례 안에서는 사람 판정과 어긋난 경우가 없었다. 사람 목록은 은퇴한 사실만 다뤘으므로, "옛 값이 활성으로 남음"(not_superseded) 분류는 비교 대상이 없다.

## 판정 불가 (unmatched)

반드시 있어야 할 값(현재 값, 다른 프로젝트 값)이 어떤 사실에도 없으면 판정 불가로 따로 센다. 옛 값이 어느 사실에도 없는 것은 저장되지 않은 것이므로 판정 불가가 아니다. 변환 규칙을 넣은 뒤 az4 기준 판정 불가는 42건 중 7건이었다. 한국어는 ko-12 한 건으로, "4천 원" 사실이 실제로 저장되지 않은 경우다(시점 조회 경로의 알려진 미지원). 나머지 여섯 건은 영어·일본어의 표기 차이다.
