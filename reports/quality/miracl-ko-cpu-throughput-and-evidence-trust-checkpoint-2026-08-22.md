## 결론

한국어 MIRACL 전체 코퍼스 기준선 실행은 CPU에서 정상 진행 중이다. 3시간 57분 시점에 Qdrant가 1,486,752개 중 276,992개를 보유해 18.6%를 완료했다. 현재 속도를 단순 연장하면 전체 적재에는 약 21시간이 필요하다. 아직 213개 질의의 정확 검색과 평가가 시작되지 않았으므로 검색 품질 수치는 없다.

처리량 후보로 Transformers의 실제 배치 추론을 시험했더니 소규모 다국어 E5 모델에서 8개 문서 처리시간이 28.55ms에서 10.11ms로 줄어 2.82배 빨랐다. 그러나 기존 개별 추론 대비 벡터 성분의 최대 절대 차이가 0.01556이었다. 양자화 모델의 배치 패딩이 출력을 바꿀 수 있으므로 이 결과만으로는 안전한 최적화가 아니다. 공통 임베딩 공급자의 기본 동작을 바꾸지 않았으며, 향후 동일 MIRACL 입력에서 검색 순위와 `nDCG@10`·`Recall@100` 비열등성을 확인한 뒤에만 채택한다.

## 실제 배치 추론 탐색

동일 프로세스에서 `multilingual-e5-small` CPU 모델을 준비한 뒤, 한국어 4개와 영어 4개 문장을 기존 개별 호출과 배열 입력 배치 호출로 각각 임베딩했다.

| 항목 | 측정값 |
|---|---:|
| 문서 수 | 8 |
| 기존 개별 호출 | 28.55ms |
| 실제 배치 호출 | 10.11ms |
| 처리시간 개선 | 2.82배 |

이 측정은 처리량 후보 탐색용 한 번의 소표본 결과다. `multilingual-e5-large`, 긴 문서 길이 분포, 검색 순위, 전체 코퍼스 품질을 대표하지 않는다.

## 채택 게이트

실제 배치 후보는 아래 조건을 모두 충족하기 전까지 기본 경로에 합치지 않는다.

1. 모델·리비전·dtype·접두사·풀링·정규화·최대 길이를 기준선과 동일하게 잠근다.
2. 한국어 전체 코퍼스의 동일 문서·질의·Qrels로 기존 방식과 후보 방식을 각각 실행한다.
3. NIST `trec_eval`로 `nDCG@10`과 `Recall@100`을 독립 재계산한다.
4. 사전등록한 비열등성 한계와 순위 안정성 기준을 통과한다.
5. 처리량은 모델 준비 시간을 제외하지 않은 동일 경계와 별도 정상상태 경계를 함께 보고한다.
6. 결과가 배치 크기나 문서 길이 정렬에 민감한지 확인한다.

## 공개 증거의 신뢰 경계

암호화된 정답, 서명, 타임스탬프는 파일 무결성과 사건 순서를 검증할 수 있지만 운영자와 독립된 보관을 스스로 증명하지 못한다. 저장소 안에서 운영자가 새 서명 키를 만들고 같은 운영자가 정답·예측·해제 키를 모두 다룰 수 있다면, 서명이 늘어도 독립성은 생기지 않는다.

공개 가능한 맹검 주장에는 최소한 다음 외부 경계가 필요하다.

- 외부 실행자가 정답을 받지 않은 평가 패킷으로 예측을 봉인한다.
- 별도 외부 보관자가 예측 봉인 시각 이후에만 정답 해제를 승인한다.
- 두 주체의 신원과 공개 키가 저장소 운영자 외부에서 확립된다.
- 제3자가 원자료와 실행 파일로 점수를 재현한다.

따라서 현재 암호화 증거는 구조 검증 단계이며 `oracleKeyWithholdingVerified: false`가 정직한 상태다. 이 저장소의 검증 코드는 외부 서명과 순서를 확인할 수 있지만 조직적 독립성이나 비공모를 만들어낼 수는 없다.

## 적대 검토 상태

- 이전 OpenCode 검토는 운영자 자체 서명, 키 소유 증명 부재, 중복 영수증, 타임스탬프 의미 과장, 키 회전·폐기 부재, 재생 방지 부족을 지적해 `REDESIGN` 결론을 냈다.
- 이번 배치 변경 검토는 영향 파일과 호출 범위를 조사했으나 최종 응답을 반환하지 못했다. 따라서 완료된 독립 리뷰로 계산하지 않는다.
- 복구 모드에서는 정식 다중 역할 `review-pass`의 입력 계약과 보존 검사가 성립하지 않으므로 상태는 `REVIEW_ONLY/NOT_CLEAN`이다.
