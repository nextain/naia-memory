# Plain-vector 6개 트랙 평가 도구 준비 증거 — 2026-08-28

상태: `IMPLEMENTED_NOT_EXECUTED`

이 체크포인트는 동일 입력 장기기억 비교에 필요한 plain-vector 기준선을 평가 도구에 추가한 구현 증거다. 실제 6개 트랙 캠페인을 실행했다는 뜻이 아니며, 비교 결과나 Naia 우위를 주장하지 않는다.

## 이번 체크포인트에서 확인한 것

- v6 경쟁 분석계획을 사용하는 새 비교의 기본 트랙은 `naia`, `mem0`, `hindsight`, `graphiti-historical`, `letta`, `plain-vector`다. 분석계획 없는 실행은 기존 projected Graphiti 진단 매트릭스를 유지하고, 서명된 v5 계획은 하위 호환을 위해 그 계획에 선언된 엔진 매트릭스를 그대로 사용한다.
- projected Graphiti는 별도의 진단 트랙으로만 남는다.
- plain-vector는 입력 turn을 그대로 한 번 임베딩해 불변 벡터로 저장한다. 추출, 통합, 갱신, 삭제, LLM 추론은 수행하지 않는다.
- 임베딩 모델·revision·차원·인증 방식·origin을 공개한다. 실행기는 `fetch`에서 관측한 임베딩 HTTP 경로를 운영 API 키와 분리된 32바이트 이상의 `BENCHMARK_EVIDENCE_HMAC_KEY`로 HMAC-SHA256 결합한다. 후단 검증기는 서명된 실행자 진술 안에서 이 결합값의 형식과 엔진 간 일치성을 확인하지만 비밀 키 없이 경로를 독립 재계산하지 않으므로, 이는 독립 증명이 아니라 실행자 증언과 경로 동등성 결속이다.
- OpenAI 호환 base URL은 `/v1` 또는 `/openai`로 끝나는 경우만 허용한다. 따라서 Naia·Mem0 SDK·plain-vector가 서로 다른 `/embeddings` 경로를 호출하면서 동일 경로라고 증명하는 구성을 거부한다.
- 분석 계획 v6는 `retrievalBaseline: ["plain-vector"]`를 명시하며, 실행 증거는 캠페인 엔진과 이 lane의 정확한 대응을 강제한다. 기존 서명된 v5 계획의 확장 허용 동작은 유지한다.

## 아직 완료되지 않은 잔여 작업

- 같은 입력·동결 계약으로 6개 트랙 실제 캠페인 실행
- 독립 작성 코퍼스와 독립 판정 절차 확보
- 충분한 반복 실행과 비용·지연시간 영수증 수집
- 결과 분석, 다중 비교 보정, 공개 주장 자격 판정
- 최종 `naia-agent` 및 `naia-shell` 배선 E2E 재검증

따라서 이 문서는 평가 도구 준비 체크포인트이며, 잔여 벤치마크나 전체 통합 완료 보고서가 아니다.

## 검증 영수증 상태

릴리스 전 구현 revision에 결합된 테스트·타입 검사·빌드 영수증을 생성해야 한다. 이 문서는 그 실행 영수증을 대신하지 않는다.
